# Contributing to ollama-response-generator-python

First off, thank you for taking the time to contribute! 🎉 Contributions are what keep the **ollama-response-generator-python** project growing and improving. Whether it's bug fixes, new features, documentation improvements, or feedback, all contributions are deeply appreciated.

Please take a moment to review the guidelines below to help make the contribution process smooth and effective for everyone.

---

## Code of Conduct

By participating in this project, you agree to abide by our **Code of Conduct**. Please treat all contributors and maintainers with respect, patience, and professional courtesy.

---

## Getting Started

1. **Check Existing Issues & Discussions:** Before starting work on a new feature or bug fix, check the existing [Issues](https://github.com/username/ollama-response-generator-python/issues) and [Discussions](https://github.com/username/ollama-response-generator-python/discussions) to see if someone else is already working on it.
2. **Open an Issue or Discussion:** If your change is non-trivial, please open an Issue or start a Discussion first to propose your idea and gather feedback.

---

## Contribution Workflow Rules

To maintain high quality and traceability across the project, please strictly follow these core rules:

* **Link PRs to Issues/Discussions:** Every Pull Request (PR) must be linked to a corresponding Issue or Discussion topic. The PR must be set up to automatically close the linked item upon a successful merge.
* **Fork & Branch Naming Convention:**
  * Always fork the `main` branch before making any edits.
  * Your working branch must follow this exact naming format:
    `[Prefix]/[AI Agent Name or "human"]/[PR Title]`
    *(Example: `fix/human/fix-response-parsing` or `feat/codex/add-async-streaming`)*

* **Branch Prefix Classifications:** When naming your branch, use one of the prefixes defined in the table below:

| Prefix | Description |
| :-: | :-- |
| `fix` | Bugfix. |
| `feat` | New feature or major enhancement. |
| `docs` | Documentation updates (README, guides, etc.). |
| `ref` | Code refactoring without behavior changes. |
| `test` | Adding or updating tests. |

* **Complete the PR Template:** When submitting your Pull Request, ensure that **all** fields and checklist items in the PR template are fully filled out. Incomplete PR templates may result in delayed reviews.
* **Transparent Communication:** Make a concerted effort to keep your related Issue or Discussion updated with your progress, plans, and any roadblocks you encounter along the way.

---

## Submitting a Pull Request

1. Push your branch to your forked repository.
2. Open a Pull Request against the `main` branch of `ollama-response-generator-python`.
3. Link the PR to your Issue or Discussion.
4. Fill out the PR template completely.
5. Wait for maintainer review, address feedback promptly, and once approved, your changes will be merged!

Thank you again for contributing to **ollama-response-generator-python**!
